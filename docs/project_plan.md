# AI Toolbox 프로젝트 기획서

## 1. 목적과 작업 환경

조원들의 AI 서비스 조사·체험 자료를 모아, 분야별로 검색하고 상세 정보를 확인할 수 있는 개인 AI 서비스 도구함을 만든다. 조사 자료는 팀 전체의 자료를 활용하되 사이트 제작은 유정현이 개인 작업으로 진행한다.

- 프로젝트 폴더: `ai_toolbox`
- 화면에 표시할 이름: `AI 서비스 도구함`
- 개발 도구: VS Code의 Claude Code를 통한 바이브 코딩
- 기술: HTML·CSS·JavaScript만 사용
- 배포 목표: GitHub 저장소와 연결한 Vercel
- 파일·폴더 이름: 영어 snake_case. 확장자와 `index.html` 등 표준 이름은 유지
- 문서와 화면 문구: 한국어 중심
- 팀 운영 규칙, 브랜치 전략, 커밋 메시지 규칙은 작성하지 않는다.

## 2. 과제 요구사항과 확정 사항

원본 발표자료 `ai서비스리스트만들기 (2).html`과 지금까지의 대화를 기준으로 정리했다.

| 항목 | 적용 내용 |
| --- | --- |
| 조사 대상 | 일반 업종 정보 사이트가 아닌 AI 서비스 |
| 자료 범위 | 조원 전체의 통합 조사 자료 반영 |
| 체험 | 최소 2개 이상 직접 사용한 서비스와 소감 포함. 체험하지 않은 기능을 체험한 것으로 작성하지 않음 |
| 개발 방식 | 코드 작성 전에 화면 구성과 파일 구조 확인 |
| 데이터 분리 | `js/services.js`에 서비스 데이터 저장 |
| 기본 기능 | 분야 필터, 검색, 요금 배지, 공식 서비스 링크, 모바일 대응 |
| 상세 정보 | 사용방법, 장점, 아쉬운 점, 직접 써본 소감, 작성자, 상세 요금 |
| 추천 용도 | 기존 분야 분류를 활용. 별도 추천 용도 항목을 새로 만들지 않음 |
| 배포 | 발표자료의 Netlify 예시 대신 교수님이 안내한 Vercel 사용 |
| 디자인 | COSTD/COSMOA의 공통 UI 방향 활용 |

로그인, 사용자 관리, 공동 편집, 서버·DB, AI API 호출은 첫 버전 범위에 포함하지 않는다. 서비스 이용은 공식 사이트로 이동해서 진행한다.

## 3. 원본 데이터

원본 통합 엑셀: `AI_서비스_통합.xlsx`. 사용자는 로컬 프로젝트에 `ai_services.xlsx`로 이름을 바꿔 넣는다.

확인 결과: 헤더를 제외한 서비스 항목 17개. 뒤쪽의 빈 행은 데이터로 세지 않는다. 같은 서비스가 서로 다른 분야나 작성자의 체험으로 존재하므로 서비스명만으로 합치지 않는다.

| 엑셀 열 | JavaScript 필드 | 처리 |
| --- | --- | --- |
| 분야 | `category_original`, `category` | 원문 보존 및 필터용 표기 정리 |
| AI 서비스이름 | `name` | 원문 보존 |
| 한줄소개 | `description` | 상세 원문 보존, 카드에서만 표시 길이 제한 |
| 사용방법 | `usage` | 순서와 줄바꿈 보존 |
| 장점 | `advantages` | 원문 보존 |
| 아쉬운점 | `limitations` | 원문 보존 |
| 직접써본소감 | `review` | 작성자의 개인 의견과 체험 범위 보존 |
| 써본사람 | `author` | 원문 보존 |
| 사용요금 | `pricing_detail` | 요금·출처·확인일 등 원문 전체 보존. "조사 당시 기록"으로 표시 |
| URL | `source_url` | 원본 링크 그대로 보존. 공유 대화·개인 문서·온보딩 주소도 수정하지 않음 |

추가 필드: `id`는 항목별 고유 식별자, `official_url`은 검증한 공식 홈페이지(공식 사이트 버튼에 사용), `pricing_type`은 배지용 분류, `pricing_summary`는 카드용 짧은 요약, `pricing_official`은 공식 페이지에서 확인한 현재 요금 정보(무료 플랜 여부, 플랜별 월간 결제 가격, 연간 결제 시 월 환산액, 통화·결제 주기, 사용량 기준), `pricing_sources`는 확인에 사용한 정확한 페이지 URL 목록, `pricing_checked_at`은 실제 확인일, `pricing_status`는 확인 상태(`확인`, `미확정`, `미확인`)다. 필드명도 snake_case를 사용한다. 각 항목의 값과 근거는 `docs/data_corrections.md`를 따른다.

### 데이터 처리 원칙

1. 엑셀의 시트·열·실제 항목 수를 먼저 확인한다. 현재 17개와 다르면 차이를 보고한다.
2. 원본 엑셀은 보존하고 CSV를 생성한다. 셀 안의 줄바꿈·쉼표·따옴표가 손상되지 않도록 표준 CSV 라이브러리를 사용한다.
3. CSV는 UTF-8로 저장한다. Excel 호환을 위해 BOM을 사용했다면 처리 결과에 명시한다.
4. 원본 조사 내용과 체험 소감은 임의로 수정하거나 새로 만들지 않는다. 조사한 특징과 직접 경험한 내용의 구분도 보존한다.
5. 표시용 분야명은 공백·줄바꿈 등만 정리하고, 의미를 바꾸는 통합은 먼저 제안한다. 원문 분야는 별도로 남긴다.
6. 값이 비어 있으면 화면에 `정보 없음`을 표시한다. 작성자·요금·URL 등을 추측해서 채우지 않는다.
7. 요금 배지는 `무료`, `유료`, `무료+유료`, `확인 필요`로 구분한다. 원문에 무료 이용과 유료 요금제가 명시된 경우 `무료+유료`로 처리한다. 유료 요금만 적혀 있다는 이유로 무료 플랜이 없다고 단정하지 않는다.
8. 상세 요금은 조사 당시 정보로 표시한다. 확인일은 원문에 있는 경우에만 표시하며 최신 가격이라고 단정하지 않는다.
9. 긴 소개·요금은 카드에서 요약하거나 줄 수를 제한하되 상세보기에서 원문을 모두 제공한다.
10. URL이 비어 있거나 유효하지 않으면 바로가기 버튼을 비활성화하고 데이터 점검 결과에 남긴다.

### URL·요금 검증 기준 (2026-10-07 추가)

검증 결과와 항목별 비교표는 `docs/data_corrections.md`에 있다. 구현 단계에서는 아래 기준을 그대로 적용한다.

1. 공식 홈페이지는 `official_url`, 원본 링크는 `source_url`로 분리한다. 공식 사이트 버튼은 `official_url`을 사용하고, `source_url`은 상세 모달에 "조사 당시 링크"로 표시할 수 있다.
2. 요금 정보는 공식 홈페이지·공식 요금 페이지·공식 도움말 본문에서 직접 확인한 것만 "확인"으로 취급한다. 검색 결과 요약, 블로그, 비교 사이트만으로는 확정하지 않는다.
3. 확인 상태는 세 가지로 기록한다. `확인`은 공식 본문에서 직접 확인, `미확정`은 공식 도메인 검색 요약만 있고 본문 인용을 못 함, `미확인`은 접근 실패 또는 스크립트 렌더링으로 본문에 금액이 없음.
4. 월간 결제 가격을 기본으로 표시한다. 연간 결제 가격은 "연간 결제 시 월 환산 약 $X"로 별도 표시하며 월 요금처럼 적지 않는다. 첫 달 할인, 신규 가입 할인, 프로모션 가격도 월 요금으로 적지 않는다.
5. 연간 결제 기준만 확인된 서비스(예: Figma Organization·Enterprise, n8n 클라우드)는 그 값을 월간 결제 가격으로 표시하지 않는다. 통화는 공식 페이지 표기를 따른다. n8n은 EUR, Gemini 한국 페이지는 KRW, 나머지는 USD.
6. Claude Pro는 월 $20 / 연 $200으로 쓰고, 연간 월 환산액을 적을 때는 약 $16.67로 표시한다.
7. `미확정`·`미확인` 플랜 가격은 카드의 `pricing_summary`에서 제외하고 `가격 확인 필요 · 공식 요금 페이지 참고`로 표시한다. 무료 플랜 존재가 공식 본문에서 확인된 서비스는 `무료+유료` 배지를 유지한다.
8. Google Stitch는 공식 페이지에 요금제 표기가 없으므로 무료로 확정하지 않는다. 배지 `확인 필요`, 요약 `요금 정보 확인 필요`로 표시한다.
9. 상세 모달의 요금 영역은 두 블록으로 나눈다. `조사 당시 기록`은 `pricing_detail` 원문을 그대로 보여주고, `공식 확인 요금`은 `pricing_official`과 확인일, 출처 URL을 보여준다. 체험 소감 안의 요금 언급(예: "무료: 인당 30크레딧", "프로-22달러")은 체험 당시 기록으로 소감 영역에 그대로 둔다.
10. 원본 엑셀과 `data/ai_services.csv`는 수정하지 않는다. 수정 전후 값, 수정 이유, 공식 출처는 `docs/data_corrections.md`에 비교표로 기록하고, 값이 바뀔 때마다 그 문서를 갱신한다.

## 4. 화면 구성

### 데스크톱

- 왼쪽 사이드바: 사이트 이름, 전체 목록, 분야별 메뉴
- 본문 상단: 페이지 제목 `AI 서비스 도구함`, 간단한 소개 문구
- 검색 영역: 서비스명·소개 검색창, 현재 분야와 검색 결과 수
- 목록 영역: 반응형 서비스 카드 그리드
- 상세 영역: 선택한 항목의 상세 모달

### 서비스 카드

- 서비스명
- 분야
- 한줄소개
- 요금 배지와 짧은 요금 설명
- `상세보기` 버튼
- `공식 사이트` 버튼

카드를 클릭하면 상세보기를 열고, 공식 사이트 버튼은 별도의 동작으로 제공한다. 공식 사이트 버튼 클릭 시 모달이 함께 열리지 않도록 처리한다.

### 상세 모달

서비스명·분야·소개를 상단에 표시하고, 사용방법 → 장점 → 아쉬운 점 → 직접 써본 소감 → 작성자 → 상세 요금 순으로 보여준다. 공식 사이트 버튼과 닫기 버튼을 제공한다. 원문의 줄바꿈과 목록 구조를 읽기 쉽게 표시한다.

### 모바일

- 사이드바를 접고 메뉴 버튼으로 분야를 선택한다.
- 서비스 카드는 한 열로 표시한다.
- 검색창과 버튼이 화면 밖으로 넘치지 않게 한다.
- 모달은 화면 너비에 맞추고 긴 내용은 내부에서 스크롤한다.
- 작은 화면에서 페이지 제목 크기를 줄여 가독성을 유지한다.

## 5. 기능 동작

### 분야 필터와 검색

- 첫 화면은 전체 항목을 원본 순서로 표시한다.
- 분야 메뉴를 선택하면 해당 분야 항목만 표시한다.
- 검색은 서비스명과 소개를 대상으로 하며 대소문자를 구분하지 않고 앞뒤 공백을 무시한다.
- 분야와 검색 조건은 동시에 적용한다.
- 검색어를 비우면 현재 분야의 전체 항목을 보여준다.
- 결과가 없으면 `검색 결과가 없습니다`와 필터·검색 초기화 버튼을 제공한다.
- 결과 수는 실제로 표시되는 조사 항목 수를 기준으로 한다. 동일 서비스의 분야별 항목도 각각 센다.

### 링크와 모달

- 공식 링크는 새 탭으로 열고 `rel="noopener noreferrer"`를 적용한다.
- HTTP/HTTPS 링크만 허용한다.
- 모달은 닫기 버튼, 바깥 영역 클릭, Escape 키로 닫힌다.
- 모달을 열 때 제목 또는 첫 조작 요소로 포커스를 이동하고, 닫을 때 원래 카드의 버튼으로 돌아간다.
- 모달 내부에서 키보드 포커스가 유지되도록 하고 배경 스크롤을 잠근다.
- 엑셀의 텍스트는 안전하게 렌더링한다. 원문 문자열을 그대로 HTML로 삽입하지 않는다.

## 6. COSTD/COSMOA 디자인 기준

다음은 이전 대화에서 확정한 참고 수치다. 이번 문서 작성 시 COSTD 원본 CSS와 폰트 파일을 다시 확인한 것은 아니므로 원본과 완전히 동일하다고 단정하지 않는다.

| 요소 | 적용 기준 |
| --- | --- |
| 페이지 배경 | `#F2F4F6` |
| 카드 | 흰색, 모서리 24px, 은은한 그림자 |
| 포인트 색상 | `#1B64DA` |
| 선택 배경 | `#E8F3FF` |
| 폰트 | 나눔스퀘어 네오 |
| 데스크톱 페이지 제목 | 38px |
| 카드 제목 | 19px |
| 본문 | 16px |
| 간격·아이콘 | 여유 있는 간격, 선 형태 아이콘 |

- 색상·폰트·간격은 CSS 변수로 관리한다.
- 버튼, 검색 입력창, 사이드바, 모달에 일관된 스타일을 적용한다.
- 요금 배지는 색상과 글자를 함께 사용한다.
- 키보드 포커스 표시와 읽기 쉬운 명암을 확보한다.
- COSTD의 색상과 UI 방향을 재사용하되 사이트 제목과 메뉴는 이번 목적에 맞춘다.
- 원본 CSS는 `reference/style.css`, 폰트는 `reference/fonts/`에 제공받을 예정이다.
- 원본 파일이 제공되면 필요한 규칙과 폰트를 확인해서 반영한다. 파일이 없으면 임시 시스템 폰트를 사용하고 미제공 상태를 보고한다.
- 나눔스퀘어 네오의 정확한 폰트 파일명과 굵기는 실제 파일 확인 후 `@font-face`에 설정한다. 원본을 임의로 찾거나 파일명을 꾸며내지 않는다.

## 7. 최종 파일 구조

사용자는 `ai_toolbox` 폴더를 VS Code에서 열었으며 Claude Code 실행까지 완료한 상태다. 하위 폴더와 파일은 Claude가 생성한다.

```text
ai_toolbox/
├── index.html
├── favicon.svg
├── ai_services.xlsx
├── docs/
│   └── project_plan.md
├── data/
│   └── ai_services.csv
├── reference/
│   ├── style.css
│   └── fonts/
├── css/
│   └── style.css
├── js/
│   ├── services.js
│   └── script.js
├── fonts/
└── img/
```

- `index.html`: 페이지 구조와 상세 모달
- `css/style.css`: 공통 디자인과 반응형 스타일
- `js/services.js`: CSV에서 변환한 서비스 데이터
- `js/script.js`: 목록 렌더링, 검색, 필터, 모달 동작
- `data/ai_services.csv`: 원본 엑셀의 텍스트 변환본
- `reference/`: 제공받은 COSTD 원본 참고 파일
- `fonts/`: 사이트에서 사용하는 제공받은 웹폰트
- `favicon.svg`: 이번 사이트의 간단한 파비콘
- `img/`: 필요한 경우에만 이미지 저장. 로고가 없으면 텍스트로 표시

첫 준비 단계에서는 엑셀과 기획서를 두고, 필요한 하위 폴더 및 CSV만 만든다. 웹 코드와 파비콘은 구현 단계에서 생성한다. 폰트 원본 파일명은 출처 추적을 위해 그대로 유지해도 된다.

## 8. Claude 작업 순서

### 1단계: 준비 및 설계 확인

1. 이 기획서를 읽는다.
2. 루트의 `ai_services.xlsx`를 읽고 시트·열·유효 데이터 수를 확인한다.
3. 사용할 수 있는 엑셀 처리 도구를 확인하고 원본을 보존한 채 `data/ai_services.csv`를 생성한다.
4. 누락 값, 중복 서비스의 분야 차이, 요금 분류가 애매한 항목을 보고한다.
5. 실제 분야 목록과 화면 구성·파일 구조를 제안한다.
6. COSTD CSS 및 폰트의 제공 여부를 확인한다.
7. 이 단계에서는 웹사이트 코드를 작성하지 않고 결과를 사용자에게 보여준다.

### 2단계: 사용자 설계 확인 후 구현

1. 확정한 구조로 HTML·CSS·JavaScript 파일을 생성한다.
2. 원본의 17개 항목을 `js/services.js`로 변환한다. `official_url`, `pricing_type`, `pricing_summary`, `pricing_official`, `pricing_sources`, `pricing_checked_at`, `pricing_status`는 `docs/data_corrections.md`의 수정안을 적용한다.
3. 검색, 분야 필터, 요금 배지, 상세 모달, 공식 링크를 구현한다.
4. COSTD 디자인 기준과 제공된 참고 파일을 반영한다.
5. 데스크톱·모바일 화면과 키보드 조작을 확인한다.
6. 데이터 누락 여부 및 동작 점검 결과를 보고하고 Live Server 실행 방법을 안내한다.

### 3단계: 배포

1. 사용자가 Live Server에서 결과를 확인한다.
2. 개인 사이트용 GitHub 저장소에 파일을 올린다.
3. Vercel에서 해당 저장소를 연결해 정적 사이트로 배포한다.
4. 배포 시점의 Vercel 화면에 맞춰 설정을 안내한다. 별도 프레임워크·서버·API 키는 필요하지 않다.
5. 배포 URL에서 화면·검색·필터·모달·외부 링크·폰트 경로를 확인한다.

이번 기획서 작성만으로 저장소 생성이나 배포를 실행하지 않는다.

## 9. 완료 기준

- [ ] 조원 전체 자료의 유효 항목 17개가 누락 없이 반영되어 있다.
- [ ] 같은 서비스의 분야별 체험이 별도 항목으로 보존되어 있다.
- [ ] 사용방법·장단점·소감·작성자·요금·URL이 원본과 대응한다.
- [ ] 직접 체험한 서비스 최소 2개와 실제 소감이 포함되어 있다.
- [ ] 원문에 없는 체험·사실·가격을 만들어 넣지 않았다.
- [ ] 검색과 분야 필터를 함께 사용할 수 있다.
- [ ] 요금 배지가 표시되며 애매한 값은 확인 필요로 남아 있다.
- [ ] 공식 사이트 버튼이 `official_url`을 사용하고, 원본 링크는 `source_url`로 보존되어 있다.
- [ ] 카드 요약에는 월간 결제 가격만 표시되고, 미확정·미확인 가격은 `가격 확인 필요`로 표시된다.
- [ ] 상세 모달에서 조사 당시 요금 기록과 공식 확인 요금이 구분되어 있다.
- [ ] 상세 모달의 긴 내용과 줄바꿈을 읽을 수 있다.
- [ ] 모달 열기·닫기 및 키보드 포커스 동작이 정상이다.
- [ ] 공식 사이트 링크가 새 탭으로 열린다.
- [ ] 모바일에서 가로 넘침 없이 목록과 모달이 보인다.
- [ ] CSS·JS·이미지·폰트 경로 오류가 없다.
- [ ] Vercel 배포 주소에서 정상 접속된다.
